## 0. 摘要（TL;DR）

- **一句话定位**：暗黑氛围电子（Dark Ambient × 微律动）——低频脉冲为骨、稀疏高音点缀为"暗夜中的色彩"，与美术"浓黑描边 + 暗夜高光"的视觉反差同构；BGM 让位于打击感音效（duck 机制方向正确）。
- **最高优先级发现（代码事实 + 已实测验证）**：合成音效采样率为 **22050 Hz**，而 pygame mixer 默认初始化为 **44100 Hz** → **全部程序合成音效与音乐以 2 倍速、高 8 度播放**。音乐"16 秒循环"实际只有约 8 秒；爆炸 55Hz 次低频实际为 110Hz，重量被削。这是当前"声音廉价感"的最主要技术根因，**P0 必须修**（属工程侧一行级修复，音频设计无需改动）。
- **音效位审计结论**：`enemy_death`（多变体）/ `boss_warning` / `boss_death` / `hurt` 设计合格；`shoot` / `pickup` / `ui_click` 纯正弦质感"廉价感"明显；`music` 概念正确但执行偏"氛围床"，单循环 5 图复用 + 无打击层，张力不足。
- **地图 BGM 变奏**：建议"1 主循环（修速率后）+ 5 张地图短氛围层（环境音 bed）"的轻量方案，而非 5 首完整编曲；需工程侧扩展音乐槽（当前仅支持单一 `music` 位）。
- **商业化**：程序合成 + Kenney CC0 → 商店视频零版权风险 ✅；但**录制任何宣传素材前必须先修 2× 速率 bug**，否则录屏会暴露音频缺陷；宣传片不得使用游戏内不存在的音频冒充。

## 1. 音乐基调（音频方向）

### 1.1 风格定位

| 维度 | 定位 | 理由 |
|---|---|---|
| 风格 | **暗黑氛围电子 / 工业氛围 × 微律动**（Dark Ambient Pulse） | 与美术"暗底 + 高光点"反差同构；幸存者品类中 BGM 应让位于打击感音效；程序合成/短循环可低成本扩展变奏 |
| 节拍骨架 | ~120 BPM 低音脉冲（现有 loop 2Hz 低音已接近此值） | 提供战斗驱动但不抢戏；可加 8 分音符噪声打击层（shaker/hat），音量 ≤ -12dB 让位 |
| 和声 | A 小调系为基底，随地图移调（见 §2） | 小调 = 暗夜基调；移调 = 低成本变奏手段 |
| 旋律策略 | **无主旋律**，以"空间感 + 律动 + 纹理"为主 | 避免旋律在 10 分钟循环中审美疲劳；给玩家注意力让位 |
| 音色 | 合成器/工业（pad/drone/脉冲/琶音），禁止管弦与写实采样 | 与程序合成技术栈一致；Kenney CC0 素材风格兼容 |

### 1.2 能量曲线（对齐 10 分钟 Boss 时间轴）

现有单循环无法表达全局长线张力。建议按 Boss 时间轴（120/240/360/480s）分层：

```
0-120s   荒芜墓地：稀疏（风、墓钟、低频 drone）→ 蓄力
120s     尸王预警：抬升（现有 boss_warning duck 已实现）
120-240s 腐化沼泽：+ 湿闷纹理、滴答随机点
240s     暗影巫师：+ 暗紫垫、咒印琶音
240-360s 暗影庭院 → 钢铁废墟：+ 金属打击层（密度升）
360s     钢铁巨像：打击层最密
360-480s 虚空裂缝：次低频 sub swell + 高频 shimmer，张力峰值
480s     虚空之主：最强压迫
胜利      归于寂静（stinger → 静音，配合设计侧胜利判定实现）
```

### 1.3 混音原则（总线/音量）

- **现状（代码事实）**：`sfx_volume=0.6`、`music_volume=0.4`；duck 表见下；pygame mixer 默认 **8 通道**（音乐占 1，SFX 实际仅 7）。
- **duck 表（代码事实）**：level_up 0.5/0.6s · explosion 0.35/0.4s · hurt 0.4/0.35s · boss_warning 0.6/1.2s · boss_death 0.7/1.0s —— 大音效压低 BGM、突出反馈，**方向正确，保持**。
- ⚠️ **duck 平滑恢复是死代码（代码事实）**：`update()` 中 timer 到期分支直接把 `_duck_amount` 置 0，"平滑恢复"分支实际不会从正值运行 → duck 结束瞬间 BGM 音量跳变。P2 打磨项。
- ⚠️ **通道不足（代码事实）**：8 通道在高密度战斗（射击 5.5/s + 击杀 3.8/s + 命中 + 爆炸）会静默丢音。建议 `set_num_channels(24)` + `set_reserved(1)` 保留音乐通道（工程侧一行级）。
- **总线结构**：pygame.mixer 无真实总线；以"通道分组 + Sound.set_volume 侧链"模拟（现有实现已如此）。文档标注为引擎约束，不强行引入中间件（项目定位纯标准库打包瘦身，v3.7 已移除 numpy）。

### 3.1 全局听感基线

- 整体因 2× 问题偏"**快、尖、薄**"；修复后整体会"**慢、低、厚**"——**这是第一优先，先修再谈其他打磨**，否则所有试听/替换决策都在错误的音高上做。
- 主观判定（🎧）：shoot/pickup/ui_click 的"廉价感"结论基于合成技法分析（纯正弦、无滤波、无分层），**需人工试听确认是否首发前必须替换**。

## 4. 关键代码事实与风险

### 4.1 采样率失配（✅ 已实测验证，P0）

- **事实链**：`audio_manager.py` `SAMPLE_RATE = 22050`（L15）→ 合成 PCM 按 22050 生成 → `pygame.mixer.Sound(buffer=pcm)` 原样进入 mixer → mixer 默认 `pygame.init()` 初始化于 **44100 Hz**（venv 实测 `mixer.get_init() == (44100, -16, 2)`）。
- **验证**：本地脚本生成 22050Hz 1 秒正弦 buffer → `Sound.get_length()` 返回 **0.5 秒** → 播放为 2× 速、+1 八度。
- **影响**：全部 11 个音效位 + 音乐循环。音乐"16 秒"实际 ~8 秒；爆炸 sub 55Hz→110Hz；shoot 800Hz→1.6kHz。
- **修复建议（工程侧，音频设计无需改动）**：将 `SAMPLE_RATE` 改为 44100（与 mixer 默认一致，包络按样本数计算故时长不变），或 `pygame.mixer.pre_init(22050,...)` 前置初始化。**推荐前者**（22050 带宽上限 ~11kHz，修复到 44.1k 顺带提升音质上限）。

### 4.2 通道不足（✅ 代码事实，P1）

- mixer 默认 8 通道；音乐占 1 → SFX 仅 7。高密度战斗会静默丢音（`Sound.play()` 无通道时失败不报错）。
- 建议：`pygame.mixer.set_num_channels(24)` + `pygame.mixer.set_reserved(1)`。

### 4.3 外部加载与回退（✅ 代码事实）

- `_load_external(name)` 按 `assets/sounds/{name}.wav` → `.ogg` 优先，缺失/异常则合成兜底（`or _generate_*`）。**回退逻辑稳健，外部替换不得破坏**。
- 局限：每槽只加载**单文件**（变体仅在合成路径存在）；外部替换 enemy_death 会丢失多变体。

### 4.4 已确认无 assets/sounds 目录（✅ 代码事实）

- 当前 100% 程序合成；设计评审 P2-1 亦记录"音频外放素材为空"。

## 6. 商业化考量（Steam 商店视频音频）

> 依据：商业化报告 §4.2（✅ 已核实"音效程序合成、无外部版权音频"）+ 美术圣经 §7.3"禁止用未在游戏中出现的元素"原则（🅢 延伸至音频）。

1. **版权状态（✅ 利好）**：程序合成 + Kenney CC0 → 商店视频可直接使用游戏内音频，零版权风险；随包分发 `assets/ATTRIBUTION.md` 即可。
2. **录制宣传素材前必须先修 A0-1**：当前 2× 速率 + 高八度会直接暴露在录屏里，宣传片将放大音频缺陷。**音频修复是宣传素材录制的硬前置。**
3. **实机演示片段：SFX 优先**：录游戏内战斗时建议 BGM 压到 ~0.2 或静音，突出打击感音效（shoot/hit/death/explosion 是卖点）；duck 机制天然支持"音效突出"。
4. **宣传片配乐：不要裸用 8s 循环 BGM**：循环感强、单调。建议为 trailer 单独选/做 30-60s 暗黑氛围乐（自制合成或 CC0 渠道），或用游戏 BGM 混音 + 淡入淡出做"实机演示"段。
5. **承诺一致性（红线）**：宣传片不得使用游戏内不存在的音效/音乐冒充；若 P0/P1 替换了外部音效，须先随版本更新再用于宣传，避免"宣传声音与游戏不符"的差评风险。
6. **规格建议（🅢）**：商店视频 1920×1080；音频 AAC 192kbps+ 立体声；响度目标约 -14 LUFS（平台惯例，标注为建议非硬性）；实机高光片段 15-30s。

## 8. 外部替换规范（若采用）

### 8.1 文件命名规范（✅ 与现有 loader 槽位严格一致）

| 槽位 | 文件名（放 `assets/sounds/`） | 格式建议 |
|---|---|---|
| shoot | `shoot.wav` | WAV PCM 16-bit 44.1kHz 单声道 ≤0.2s |
| hit | `hit.wav` | WAV ≤0.15s |
| enemy_death | `enemy_death.wav`（或多变体，见下） | WAV ≤0.4s |
| level_up | `level_up.wav` | WAV ≤1s |
| explosion | `explosion.wav` | WAV ≤1s |
| pickup | `pickup.wav` | WAV ≤0.3s |
| hurt | `hurt.wav` | WAV ≤0.4s |
| boss_warning | `boss_warning.wav` | WAV ≤1.2s |
| boss_death | `boss_death.wav` | WAV ≤1.5s |
| ui_click | `ui_click.wav` | WAV ≤0.15s |
| music | `music.ogg` | OGG Vorbis 44.1kHz 立体声、无缝循环 |

- **大小写**：小写蛇形；**命名即槽位**，改文件名 = 换槽。
- **回退安全**：任何文件缺失/损坏 → 该槽自动合成兜底（✅ 现有 `or _generate_*` 逻辑）。**外部替换不得删除合成路径。**

### 8.2 多变体约定（🅢 建议，需工程约 30 分钟支持）

- 命名：`shoot_01.wav ... _03.wav`、`enemy_death_01.wav ... _05.wav`。
- 加载：loader 按 `{name}_%02d` 扫描，命中则随机/轮询播放；缺失则回退单文件 → 合成。
- 目的：保留现有 `enemy_death` 多变体亮点（§3 #3），并让 shoot 在高频触发时免于机械重复。

### 8.3 推荐 CC0 来源（✅ 与商业化报告"零版权"声明兼容）

| 渠道 | 适用 | 注意 |
|---|---|---|
| Kenney（kenney.nl） | UI Audio（ui_click）、Impact Sounds（hit/explosion）、Sci-fi Sounds（shoot）、RPG Audio（pickup/level_up） | 全 CC0，首选 |
| freesound.org | 搜索时**只选 CC0 标签** | ⚠️ 大量为 CC-BY（需署名，会污染"无版权风险"声明），勿混用 |
| OpenGameArt.org | CC0 音效包 | 需人工试听筛选 |
| 自产合成 | 用 DAW 或脚本合成替换 | 完全可控，符合技术栈 |

- 素材入库后更新 `assets/ATTRIBUTION.md`（商业化报告 §4.2 已有该文件惯例）。
